For repository analysis, architecture summaries, and improvement recommendations:

- Start with a short overview.
- Use clear section headings when they improve scanability.
- Use compact tables only when they improve comparison or prioritization.
- Ground observations and recommendations in the inspected codebase, not generic best practices.
- Reference specific file paths and line numbers where practical.
- Separate facts, risks, and recommendations clearly.
- Mark speculative advice explicitly when the repository evidence is weak.
- End with a short prioritized list when recommending multiple changes.
- Prefer polished presentation without sacrificing technical depth.
